# Pic Poster Redbook

在 NAS Docker 环境中扫描照片目录，先筛选有质量和可见故事性的照片，再按拍摄事件规划统一横/竖方向的图文笔记。系统采用人工交接：从待发布队列导出原图和发布信息，在你自己的浏览器打开小红书网页，手动暂存或发布后回系统明确确认结果。系统不会自动点击小红书按钮。

小红书网页草稿保存在执行暂存操作的浏览器本地，不会因登录同一账号而自动出现在其他浏览器或手机中。当前流程不依赖 NAS 小红书登录会话；历史会话及记录保留，旧自动提交接口返回 410。

## 三项发布规则

  - **好照片和故事性**：本地检查分辨率、曝光、清晰度和方向，再用支持图片输入的视觉模型评估质量、构图、故事性和主题。故事性继续参与综合评分（权重 20%），但不再作为独立硬门槛；模型未配置或返回不合规 JSON 时，照片停在 `needs_analysis`，不会自动发布，单张照片最多自动尝试 5 次。
- **美学价值**：视觉模型单独评估光影、色彩和谐、视觉平衡、层次、节奏、留白、视觉焦点、形式感和整体完成度。默认美学分数低于 68 的照片不会进入发布预览；可通过 `MIN_AESTHETIC_SCORE` 调整。
- **同一拍摄事件最多三篇**：默认将相隔不超过 6 小时、GPS 距离不超过 300 米的照片归为同一事件。配额记录在 SQLite 的 `posts` 表中，跨重启有效；文件 SHA-256 和感知哈希防止同一照片或近似照片再次发布。
- **每篇方向一致**：每篇笔记只取同一事件、同一主题、同一方向的照片，默认最多 6 张；接近正方形的照片不进入横图/竖图批次。人工确认时再次校验照片与配额，手动接口也不能绕过规则。

## 其他功能

- 递归扫描 NAS 指定目录，支持 JPG、JPEG、PNG、WEBP、HEIC、HEIF。
- 读取并保存可解析的完整 EXIF 字段（包括 `DateTimeOriginal`、`CreateDate` 和 GPS），并用 OpenStreetMap Nominatim 反向解析地点。照片详情页将地点显示为 GPS 经纬度坐标，不展示原始 EXIF 列表。
- SQLite 保存照片分析、拍摄事件、发布笔记、失败和待人工核验状态。
- 每篇笔记提供“准备发布”：查看按顺序排列的照片，下载包含原图及标题、文案、话题、地点、操作说明的 ZIP，并单独复制各项文字。上传及保存由你在自己的小红书网页中完成；话题、地点须在平台搜索并点选真实候选。
- 下载、复制、打开发布页不修改任何笔记状态。你明确勾选并点击“确认已暂存”或“确认已发布”后，系统才原子更新记录和照片状态，写入人工确认时间；已暂存不等于已发布。旧版本或重复请求会被校验，重复确认不会重复记账。
- 发布记录区分“人工确认已暂存”和“历史 NAS 本地暂存”。历史本地草稿也可导出素材；人工暂存的笔记实际发布后，可再次打开交接窗口确认已发布，不会额外消耗拍摄事件配额。
- 当前固定为人工交接模式：计划时间只用于安排队列，不会自动操作小红书；`PUBLISH_ENABLED=true` 也不会重新启用自动暂存。
- 内置中文 Web 前端，提供“照片库”“待发布队列”“发布记录”三个独立导航入口，分别对应 `/photos`、`/queue`、`/publications`。首页默认打开照片库；支持直接访问、刷新和浏览器前进/后退，每个页面只加载自身内容。切换页面时保留照片筛选、分页和发布状态筛选。
- “运行配置”二级窗口支持视觉模型 URL、模型名、API Key、小红书账号备注、计划周期和计划时间。保存后立即生效，配置持久化到 `settings.json`；API Key 不会通过查询接口返回。
- “扫描评分”和“筛选发布”是两个独立任务。扫描评分每天按 `SCORING_SCHEDULE` 扫描未发布照片，按拍摄时间从队尾向队首处理，默认每轮最多 500 张。只有续扫指针右侧的失败照片优先重试，重试不移动续扫指针；指针左侧的失败照片等正常扫描到达时处理。成功照片不重复评分，失败达到 5 次自动跳过。
- 照片库顶部支持“停止扫描”和“继续扫描”。停止会中断当前模型请求，不增加失败次数，也不移动续扫指针；已完成结果和本轮剩余任务保存到 SQLite，重启后仍可继续，沿用原批次的数量上限。手动停止后，定时评分任务也会保持暂停，直到点击继续。
- 筛选发布每天按 `SELECTION_SCHEDULE` 遍历已经评分的照片，按拍摄时间和地点归组，选择评分高且方向、主题一致的照片生成 `draft` 草稿，并写入计划发布时间。草稿可在“待发布队列”中查看和编辑；如果照片没有 GPS，则只按拍摄时间归组，不虚构地点。
- 小红书账号标识仅作备注。请在自己的浏览器完成登录；系统不再提供自动扫码、自动暂存或自动发布入口。
- 照片库顶部提供唯一的“立即扫描”入口，显示当前目录、文件名、拍摄时间和扫描进度；灰色未扫描、绿色完成、黄色失败，并标出续扫指针。
- 索引目录后，待评分照片按拍摄时间从新到旧处理；相同拍摄时间按照片 ID 倒序，缺少或无效拍摄时间的照片排在最后。新增照片会被补扫，避免因持久化指针漏掉新文件。视觉模型请求要求 `quality`、`composition`、`story`、`aesthetics` 使用 0 到 100 的 JSON 数字，并优先发送 `response_format: {"type":"json_object"}`，单张响应期限为 100 秒。

## NAS 部署

1. 复制环境文件并按 NAS 实际路径修改：

   ```bash
   cp .env.example .env
   # NAS_PHOTO_PATH=/volume1/photo/travel
   # NAS_DATA_PATH=/volume1/docker/pic-poster/data
   ```

2. 构建并启动：

   ```bash
   docker compose up -d --build
   curl http://NAS_IP:8787/health
   ```

3. 首次必须保持 `PUBLISH_ENABLED=false`，配置视觉模型后先扫描和检查：

   ```bash
   curl -X POST http://NAS_IP:8787/api/scan
   curl http://NAS_IP:8787/api/photos?limit=20
   curl http://NAS_IP:8787/api/publish-preview
   ```

视觉模型接口采用 OpenAI-compatible `chat/completions` 请求格式：设置 `VISION_API_URL`、`VISION_MODEL` 和可选的 `VISION_API_KEY`。模型必须返回 `quality`、`composition`、`story`、`summary`、`observations`、`theme`、`reason` JSON 字段。只发送缩略图，原图不会离开 NAS。

可在前端保存视觉模型配置，随后点击“立即扫描评分”。计划周期支持每天、每 2 天、每 3 天和每周，提交后即时生效；计划时间仅用于队列安排，不触发小红书操作。

默认每天 02:00 扫描评分、03:00 筛选入队（Asia/Shanghai）。`MAX_SCORING_PHOTOS_PER_RUN` 设置评分上限，最大 500。`MAX_IMAGES_PER_POST` 设置每篇照片数；`EVENT_GAP_HOURS`、`EVENT_RADIUS_METERS` 调整事件归组。质量、美学、构图、综合分门槛可配置；故事性只参与总分，不设独立门槛。

## 人工交接操作

1. 打开待发布队列，编辑并保存笔记。
2. 点击“准备发布”，下载照片包，解压到自己的电脑。
3. 点击“打开小红书发布页”，在自己的浏览器登录，按编号上传照片并填写内容。
4. 在小红书搜索并选择话题、地点，点击暂存或发布并确认成功。
5. 回交接窗口点击对应确认，勾选操作成功后记录结果。未完成时直接关闭窗口，笔记保留在队列中。

## HTTP 接口

首页的“照片库”按实际文件展示所有支持的图片（包括尚未导入或评估的文件）。相同内容的多个文件保留各自目录，共享已有分析结果。目录可包含子目录，筛选可以组合使用；时间类型支持拍摄、文件修改和分析时间，日期按配置的 NAS 时区计算。缺少拍摄时间的照片不会匹配拍摄日期范围，缺少 GPS 的照片可以通过“无地点和 GPS”查找。

“已扫描”表示已尝试图像分析，不代表模型评分成功。评价状态区分尚未评估、已评估、评估失败和技术筛选未通过。详情包括各项评分、模型描述、理由、可见证据、技术指标及错误原因。照片库每页 48 张，使用 JPEG 缩略图；“更新图片列表”只更新文件列表，不调用模型。文件目录列表最多每分钟自动更新一次。

所有筛选条件同时生效，按日期浏览无需先扫描或评分，结束日期包含当天。查询结果上方会列出已执行的筛选条件；表单修改后需点击“查询照片”应用。时间范围叠加其他条件而无结果时，页面会核对仅按时间查询的数量，并提供“保留时间范围，清除其他筛选”按钮。

在照片库顶部拖动扫描队列的圆形指针，松开后立即保存起点（也支持方向键）。界面从左向右显示：较新照片在左、较早照片在右；仅反转显示，后端仍按时间从新到旧扫描。已成功评分的照片始终跳过，手动起点左侧未扫描的照片不会被自动插队。指针左侧失败照片仍按原规则优先重试，且重试不移动指针。扫描中移动会中断当前请求、重排剩余任务并自动继续，不增加失败次数，也不重置本轮额度；停止时移动会保持停止，需手动继续。位置和剩余任务在容器重启后保留。

待发布队列支持勾选至少两篇笔记，点击“合并所选笔记”，从原草稿照片中逐张选择合并后的照片。允许跨时间、地点和主题合并，但须统一横竖方向，并遵守每篇图片数、评分、去重和每个拍摄事件最多三篇的规则。合并窗口可编辑标题（允许留空）、文案（最多 50 字）和计划时间；话题默认沿用第一篇，原地点不同时清空地点标记，后续可在编辑草稿中调整。确认时在一次数据库事务内替换所选草稿；未入选的原照片和评分保留，可被后续筛选再次选中。草稿已被其他操作修改或处理时，合并会拒绝并保留原数据。合并本身不会连接或发布到小红书。

待发布清单及编辑草稿中的照片均可点击打开详情。已扫描且有技术信息的照片可人工修改质量、构图、审美、故事性和技术分，保存后按 20%/20%/30%/20%/10% 自动计算综合分，并重新判断入选资格。人工调整保存到数据库，保留原模型文字评价及分析时间，不消耗重试次数；详情标明调整时间，模型请求不会覆盖人工评分。已发布照片的发布状态不受评分修改影响。

建议把 8787 端口只暴露在 NAS 局域网，或通过 NAS 反向代理加认证。不要把小红书会话目录提交到 Git，也不要把接口直接暴露到公网。

## 边界

- 没有拍摄时间的照片仍会入库，但会标记 `needs_metadata`，不会自动占用拍摄事件配额或发布；没有 GPS 但有拍摄时间的照片按时间归组，可以进入待发布队列，文案不填写地点。
- “好照片”、美学价值和故事性是筛选建议，不是事实判断；阈值需要用你的照片库校准。模型被要求只根据可见证据评分。故事性不设独立硬门槛，但其 20% 综合评分权重保持不变。
- Nominatim 有使用频率限制；大量照片应配置自己的地理编码服务或改为本地地图服务。
- 建议地点来自 EXIF GPS 反向编码。交接内容是话题与地点关键词；最终标签由你在小红书网页搜索并选择，不自动认证关键词已经匹配。
